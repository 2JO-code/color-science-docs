用語索引

1. 色空間#

RGB の数字だけでは色は決まらない#

画像の 1 ピクセルは、たとえば R=0, G=133, B=165 のような 3 つの数字 (コード値) で表されます。 ところが、この数字だけでは「どんな色か」は決まりません。 「R を最大にしたときの赤がどんな赤か」「白はどんな白か」 という約束がないと、ディスプレイごとに違う色になってしまうからです。

この約束をまとめたものが色空間 (RGB 色空間) です。中身は次の 3 つです。

要素意味
原色 (primaries)R・G・B それぞれを最大にしたときの、正確な色
白色点 (white point)R=G=B=最大のときの白が、どんな白か (3 章)
トーンカーブコード値と実際の光の強さの関係 (5 章)

色域 (gamut)#

色空間が表せる色の範囲を色域といいます。原色が鮮やかなほど色域は広くなります。

色空間色域の広さ主な用途白色点
sRGB標準一般的なモニター、Web、多くの画像D65
Display P3sRGB より広い (特に赤・緑)Mac・iPhone などの広色域ディスプレイD65
Adobe RGB (1998)sRGB より広い (特に緑〜シアン)写真・印刷D65

同じ色でも、色空間が違えばコード値は変わります。たとえば ColorChecker の cyan は、sRGB では表せない (色域外) のに、Display P3 なら表せます。

このツールでは: --space で色空間を選びます。対応表は src/colorchart/spaces.py の SPACES です。

2. XYZ と Lab — 色を「見え方」で表す#

RGB は「どの機械で、どう光らせるか」に依存します。そこで、人の目にどう見えるかで色を表す方法が作られました。

CIE XYZ#

  • CIE (国際照明委員会) が 1931 年に定めた、人の目の感度をもとにした色の表し方です
  • どんな色空間の色も XYZ に変換できます。そのため、色空間どうしの通訳 (共通語) として使われます
  • ただし、XYZ で数値が同じだけ離れていても、見た目の違いは同じになりません

CIE Lab (L*a*b*)#

XYZ を、数値の差が見た目の差に近くなるように作り変えたものです (1976 年)。

軸意味範囲の目安
L*明るさ。0 = 黒、100 = 白0〜100
a*赤み (+) ⇔ 緑み (−)およそ −128〜+127
b*黄み (+) ⇔ 青み (−)およそ −128〜+127
  • a* = b* = 0 なら、色みのないニュートラル (グレー) です
  • 例: ColorChecker の cyan は L*=49.57, a*=-29.71, b*=-28.32。中くらいの明るさで、緑みと青みがある色です
  • Lab は「どの白を基準にするか」(3 章) を決めないと値が決まりません

このツールでは: すべての基準値を Lab で持っています (src/colorchart/patches.py の Patch.lab)。 gray-ramp は L* を 0〜100 で等間隔に並べたものなので、見た目の明るさが等間隔のグレーになります。

3. 白色点と色順応#

白色点 (D50 と D65)#

「白」にもいろいろあります。昼の青っぽい白と、夕方の黄色っぽい白は違う色です。 色の世界では、基準になる白を標準イルミナント (標準の光) で表します。

名前おおよその色温度どんな光か主な使われ方
D656500 K曇り空の昼光。やや青みsRGB・Display P3・Adobe RGB の白、ディスプレイ
D505000 K晴れた日の昼光。やや黄み印刷、ICC の PCS (4 章)

(K = ケルビン。光の色を温度で表したもの。数字が大きいほど青白い)

色順応 (chromatic adaptation)#

人の目は、部屋の照明が多少黄色くても、白い紙を「白」と感じます。光に目が慣れるこの働きを色順応といいます。

色の計算でも同じことをします。D65 の白を基準にした色を、D50 の白を基準にしたらどう見えるかに換算する計算です。 この換算方法を CAT (Chromatic Adaptation Transform、色順応変換) といい、いくつか種類があります。

方法特徴
BradfordICC プロファイル (v4) が採用している標準的な方法
CAT02CIECAM02 という色の見えのモデルで使われる方法
von Kries古典的でシンプルな方法

方法が違うと、結果の数値がわずかに変わります。そのため、どの方法を使ったかを固定して記録することが信頼性につながります。

このツールでは: 基準の白は ICC D50、色順応は Bradford に統一しています (spaces.py の D50_XY と CAT)。 D65 の色空間 (sRGB など) に書き出すときは、Bradford で D50 → D65 に換算しています。 JSON の reference_white と chromatic_adaptation に、何を使ったかを記録しています。

白色点の一覧#

D50・D65 のほかにも、よく使われる白があります。「D」は Daylight (昼光) の頭文字で、後ろの数字は色温度の上 2 桁です。

名前おおよその色温度どんな光か主な使われ方
D505000 K晴れた日の昼光。やや黄み印刷、ICC の PCS。このツールの基準
D555500 KD50 と D65 の中間の昼光写真 (昼光用フィルム・ストロボ)
D656500 K曇り空の昼光。やや青みディスプレイ、sRGB、テレビ
D757500 K北向きの窓から入る空の光。青みが強い色見本を比べる観察ブース
A2856 K白熱電球。オレンジ色の強い光室内照明の代表、測定器の検査
C約 6774 K昔の昼光の標準 (D65 より前に使われた)古い規格・古い測定値

色温度だけでなく、光にどの色 (波長) がどれだけ含まれるか (分光分布) も、それぞれ CIE が数表で決めています。 A は赤い側の光が多く青い側が少ない、D65 は青い側も多い、という違いがあります。

分光反射率#

物の色は、物そのものだけでは決まりません。どんな光で照らすかと、物が光をどう跳ね返すかの組み合わせで決まります。

  • 光は、虹のように色 (波長) ごとに分けられます。人の目に見えるのはおよそ 380〜780 nm (ナノメートル) です
  • 物が、波長ごとに光を何 % 跳ね返すかを表したものを分光反射率といいます。たとえば赤い紙は、長い波長 (赤) をよく跳ね返し、短い波長 (青) はあまり跳ね返しません
  • 目に届く光 = 照明の分光分布 × 物の分光反射率。これを人の目の感度 (観測者) で重み付けして足し合わせると、XYZ が計算できます
照明の光 (波長ごとの強さ) × 分光反射率 (波長ごとに何 % 跳ね返すか) ──▶ 目の感度で集計 ──▶ XYZ ──▶ Lab

分光反射率がわかっていれば、どんな照明の下の色でも計算で求められます。そのため、分光反射率は色の情報として最も詳しいものです。

方法 A と方法 B#

D50 の Lab 値を別の白色点 (たとえば照明 A) の値にしたいとき、2 つの方法があります。

方法 A (色順応で換算)方法 B (分光から計算)
やることD50 の Lab を、Bradford の色順応で別の白に置き換える分光反射率 × その照明の分光分布から計算し直す
必要なデータLab (または XYZ) だけ分光反射率
答えている問い「目がその照明に慣れたとき、同じ見え方にするにはどの値か」「その照明の下で実際に測ったら、どの値になるか」
使える範囲すべてのチャート分光データがあるチャートだけ

2 つの答えは、D50 に近い白ではほぼ同じですが、D50 から離れるほどずれます。 色順応は「白がずれた分を、すべての色に同じ割合で当てはめる」という近似なので、波長ごとの細かい違いまでは再現できないからです。 特に照明 A は青い光がとても少ないため、青や紫の色ほどずれが大きくなります。

参考までに、babelcolor-avg (24 色) で 2 つの方法の差を ΔE2000 (8 章) で測ると、次のようになります。

白色点平均最大
D500.040.17
D650.571.38
A1.603.76

D50 の差が 0 でないのは、分光データと Lab の基準値が、別々に測られた値だからです。

観測者#

XYZ を計算するときに使う「人の目の感度」の数表を、標準観測者といいます。

名前内容
CIE 1931 2°視野 2° (腕を伸ばした先の親指の爪くらい) の小さな色を見たときの感度。最もよく使われる
CIE 1964 10°視野 10° の大きな色を見たときの感度

観測者が違うと、同じ分光データからでも XYZ が少し変わります。

このツールでは: whitepoints.py に 6 種類の白色点 (WHITE_POINTS) があります。方法 A は adapt_lab、方法 B は spectral_lab です。 観測者は CIE 1931 2° に統一しています (OBSERVER)。照明の分光分布と白色点の座標は、colour-science の CIE の定義から取っています。 colorchart reference で作る一覧 (チャート一覧) は、6 種類の白色点すべてについて Lab 値を載せています。

4. ICC プロファイルと PCS#

ICC プロファイル#

ICC (International Color Consortium) が定めた、「この画像・この機器の色はこう解釈してください」という説明書のファイルです。 画像に埋め込むと、カラーマネジメント対応のソフトがそれを読み、正しい色で表示します。

  • プロファイルが付いていない画像は、多くのソフトで sRGB とみなされます
  • だから、Display P3 の画像にプロファイルが付いていないと、色がくすんで (または違って) 見えることがあります

PCS (Profile Connection Space)#

ICC の仕組みでは、色を変換するときいったん共通の言葉 (PCS) を経由します。

カメラの RGB ──▶ PCS (D50 基準の XYZ / Lab) ──▶ ディスプレイの RGB

この PCS の白が D50 と決められています。これが、印刷や色管理の世界で D50 がよく使われる理由です。

このツールでは: 基準値を PCS と同じ「D50 基準の Lab」で持っています。 sRGB を選んだときだけ、PNG に sRGB の ICC プロファイルを埋め込みます (render.py の _icc_bytes)。

5. ガンマ (トーンカーブ)#

人の目は暗い部分の違いに敏感#

光の強さが 2 倍になっても、人の目には「2 倍明るい」とは見えません。人の目は暗いところの変化に敏感です。

そこで RGB 色空間では、光の強さをそのまま数値にせず、暗い部分に多くの段階を割り当てるカーブをかけてから記録します。 これをガンマ、またはトーンカーブといいます。専門的には CCTF (Colour Component Transfer Function) と呼びます。

呼び方意味
線形 (linear) な値光の強さに比例した値。色の計算 (行列) はこちらで行う
エンコード済み (非線形) の値カーブをかけた値。画像ファイルに入っているのはこちら
色空間カーブ
sRGB暗部だけ直線、残りは約 2.4 乗のカーブ (全体として約 2.2 相当)
Display P3sRGB と同じカーブ
Adobe RGB約 2.2 乗 (正確には 563/256)

例: 明るさ L*=50 の中間グレーは、光の強さとしては白の約 18% ですが、sRGB のコード値では約 119 (255 の約 47%) になります。

このツールでは: lab_to_rgb は apply_cctf_encoding=True、rgb_to_lab は apply_cctf_decoding=True として、カーブのかけ外しを colour-science に任せています。 L*=50 が sRGB で 0.4664 (≒ 119/255) になることは、既知値テスト (tests/test_spaces.py の test_srgb_mid_gray_known_value) で確かめています。

6. 変換行列#

XYZ ⇔ RGB は 3×3 の行列で計算する#

線形な RGB と XYZ は、3×3 の数表 (行列) を掛けることで互いに変換できます。この行列は、色空間の原色と白色点から計算で求まります。

規格書の丸め行列と導出行列#

ここに落とし穴があります。

種類中身問題
規格書の行列規格書に載っている、小数 4 桁で丸めた行列丸めのせいで、白 (L*=100) が R=0.99984, G=1.0001 のようにわずかにずれる。グレーにかすかな色が付く
導出行列原色と白色点から計算した、丸めていない行列白・グレーが正確にニュートラル (R=G=B) になる

colour-science は、sRGB と Adobe RGB では規格書の行列を既定で使います。

このツールでは: グレーの正確さを優先して、導出行列に統一しています (spaces.py の _space で use_derived_transformation_matrices(True))。 どの色空間でも L*=50 のグレーが R=G=B になることを、テスト (test_neutral_gray_stays_neutral) で確かめています。

7. 量子化とクリップ#

量子化 (quantization)#

計算で求めた RGB は 0.4664... のようななめらかな数値です。画像ファイルには整数しか入らないので、段階のある値に丸めます。これを量子化といいます。

  • ビット深度: 1 色に何ビット使うか。8bit なら 28 = 256 段階 (0〜255)、16bit なら 65536 段階
  • 量子化すると、もとの値から最大で半段階ずれます。これが誤差 (ΔE) の主な原因です
    • 8bit では ΔE2000 で 1.0 未満 (実測の最大は 0.6〜0.8 程度)。目で見て違いがわかるほどではありません
    • 16bit では 0.01 未満 (実測の最大は 0.003 程度)。1 段階が 8bit の約 257 分の 1 になるためです
  • 32bit (浮動小数): 整数に丸めず、0〜1 の小数 (float32 = 有効数字およそ 7 桁の小数) のまま保存します。 ずれは ΔE2000 で 0.0001 未満 (実測の最大は 0.00001 程度) で、実質ゼロです
  • リニアとガンマ補正: 画像の値には普通、暗い部分を細かく表すために「ガンマ補正」(明るさを曲線で変換すること) がかけてあります。 EXR では補正をかけないリニア値 (光の量に比例した値) で保存する決まりがあり、このツールも EXR だけリニアで書きます。 例: L*=50 のグレーは、ガンマ補正済みの sRGB では 0.466、リニアでは 0.184 になります

四捨五入の方式 (half-up)#

ちょうど半分 (x.5) のとき、どちらに丸めるかには流儀があります。

方式126.5 の丸め127.5 の丸め使われる場所
half-up (切り上げる四捨五入)127128学校で習う四捨五入
偶数丸め (banker's rounding)126128Python の round()、NumPy の np.round()

Python の round() をそのまま使うと、学校の四捨五入と結果が違うことがあります。流儀を決めて固定しないと、同じ色でもツールによってコード値が 1 ずれます。

クリップ (clip)#

色域外の色は、計算すると RGB が 0 未満や 1 を超えた値になります。 例: ColorChecker の cyan を sRGB に変換すると R = -0.178 になります。

画像には 0〜1 の範囲しか入らないので、範囲の端に切り詰めます (-0.178 → 0)。これをクリップといいます。 クリップすると色が変わるので、ΔE が大きくなります (cyan は 3.4)。

このツールでは: spaces.py の quantize で、floor(値 × 255 + 0.5) という式で half-up の四捨五入をしています。 クリップしたパッチには必ず clipped: true の印を付け、画面にも警告を出します。色域外を黙って丸めないのが約束事です。 動きはテスト test_quantize_half_up_and_clip_flag で確かめています。

8. ΔE2000 — 色の差を測る#

ΔE とは#

2 つの色の違いを 1 つの数字で表したものです (Δ = 差、E = ドイツ語の Empfindung「感覚」)。小さいほど似た色です。

計算方法の移り変わり#

名前年特徴
ΔE*ab (CIE76)1976Lab 空間での単純な直線距離。鮮やかな色の差を大きく見積もりすぎる
ΔE94 (CIE94)1994明るさ・鮮やかさ・色合いで重みを変えた
ΔE2000 (CIEDE2000)2001さらに青の領域やグレー付近の補正を加え、人の見え方に最も近い。現在の標準

目安#

ΔE2000見え方の目安
1 未満ほとんどの人が違いに気づかない
1〜2並べてよく見ると気づく
2〜3.5並べると違いがわかる
5 以上別の色に見える

(あくまで目安です。色の種類や見る環境で変わります)

このツールでは: 基準の Lab と、コード値から計算し直した Lab の差を、colour-science の delta_E(..., method="CIE 2000") で計算しています (spaces.py の encode)。 JSON ではパッチごとの値が delta_e00、全体の値が summary.max_delta_e と summary.mean_delta_e です。

9. ColorChecker#

  • 撮影や校正で世界中で使われている、24 色のパッチが並んだ実物のカードです。1976 年に Macbeth 社が発売しました (現在は Calibrite ブランド)
  • 肌色・空の青・植物の緑など、身の回りによくある色と、6 段のグレーでできています
  • 2014 年 11 月に製造元が顔料の配合を変えたため、それ以前と以後でパッチの基準値が少し違います。どちらの基準値を使ったかを区別する必要があります
  • 6 段のグレーには、neutral 5 (.70 D) のように濃度 (D) が名前に付いています。濃度は光をどれだけ吸収するかを表す数値で、大きいほど暗い色です

このツールでは: colorchecker24 プリセットは、colour-science に収録されている「2014 年 11 月以降」の基準値 (D50 の xyY) を Lab に変換して使っています (patches.py の colorchecker24)。 JSON の source に出典を書いています。基準値が正しく読み込めているかは、既知値テスト (tests/test_patches_render.py) で確かめています。

10. このツールの信頼性の考え方#

ここまでの知識をもとに、colorchart がなぜこう作られているかをまとめます (ツールの CLAUDE.md の「色管理の約束事」を説明したものです)。

約束 1. 基準値は Lab (D50) で持つ#

RGB で持つと、色空間が変わるたびに値が変わります。見え方で決まる Lab で持てば、どの色空間に書き出しても同じ基準から出発できます。 白を D50 にしているのは、ICC の PCS と同じにして、ほかの色管理ツールと話を合わせるためです。

約束 2. 白と色順応の方法を固定する (D50 + Bradford)#

方法を混ぜると、数値が少しずつずれて、どこでずれたのか追えなくなります。1 つに固定し、JSON に記録します。

約束 3. 色変換は実績のあるライブラリ (colour-science) に任せる#

行列や定数を自分で書き写すと、打ち間違いが起きます。広く使われ、検証されているライブラリを使います。 自前で書く場合は、出典と検証テストを必ず付けます。

約束 4. 導出行列を使う#

規格書の丸め行列ではグレーにかすかな色が付きます。チャートのグレーは「本当にグレー」でなければならないので、導出行列を使います (6 章)。

約束 5. 丸め方を固定し、色域外は必ず知らせる#

half-up で丸め方を固定し、クリップしたら印を付けます。「黙って正しくない色を出す」ことが、チャートにとって最も危ないからです (7 章)。

約束 6. 往復して確かめ、結果を残す#

基準 Lab ──▶ RGB コード値 ──▶ (逆変換) ──▶ 実際の Lab
   └──────────── ΔE2000 で比べる ◀────────────┘

作った値を逆方向に変換して基準と比べる (往復検証、round-trip) ことで、どれだけ正確に作れたかを数字で示します。 その結果を PNG と一緒に JSON で残し、JSON の値が画像のピクセルと一致することをテストで確かめています。

約束 7. 追加したら必ずテストする#

新しいプリセットや色空間を足すときは、次の 2 種類のテストを足します。

テスト何を確かめるか
既知値テスト広く知られた正解の値と一致するか (例: L*=50 → sRGB 0.4664)
往復テスト変換して戻したら元の値に戻るか
